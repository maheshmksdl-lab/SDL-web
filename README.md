# SDL Web

The public Social DNA Labs website. Next.js 16, App Router, **port 3000**.

Its job is to reproduce the HTML design in `sdl-2.0` exactly, driven by content from the CMS.

## Structure

```
web/
├─ app/
│  ├─ layout.tsx                fonts, globals.css, chrome, JSON-LD
│  ├─ [[...slug]]/              THE page route — every CMS page resolves here
│  ├─ insights/[slug]/          article detail (the one non-builder route)
│  ├─ api/preview/              draftMode enable (signed)
│  ├─ api/exit-preview/
│  ├─ api/revalidate/           webhook target for CMS publishes (signed)
│  └─ api/forms/[slug]/         form submission — validate, rate-limit, create lead
├─ proxy.ts                     Next 16's rename of middleware.ts (Node runtime only)
├─ components/
│  ├─ chrome/                   SiteHeader, MegaMenu, MobileNav, SiteFooter
│  ├─ sections/                 one folder per block — index.tsx + section.css
│  ├─ ui/                       Kicker, SectionTitle, CtaLink, PillButton, ArrowButton
│  ├─ motion/                   RevealObserver, HeroCanvas, ServicesDnaVisual
│  └─ render-blocks.tsx         blockType → component dispatch
├─ lib/
│  ├─ cms/                      client, pages, globals, insights, tags, resolvers
│  ├─ registries/               icons, motifs, mocks, visuals, swatches
│  └─ payload-types.ts          generated by the CMS, copied in by CI — do not edit
├─ styles/
│  ├─ tokens.css                design tokens, verbatim
│  ├─ base.css                  resets and element defaults, verbatim
│  ├─ chrome.css                header/footer/section shells, verbatim
│  └─ sections/                 one stylesheet per block, verbatim
├─ public/                      favicon and static assets only — design media lives in the CMS
├─ e2e/                         Playwright
└─ tests/                       Vitest unit + component
```

## Conventions

### Styling — verbatim CSS, original class names

The design's CSS is lifted **as authored**, keeping `.sdl-hero`, `.ai-cap-grid`, `.evoq-mk-panel`
and every value exactly. No Tailwind, no CSS Modules, no CSS-in-JS. Every translation layer is a
chance for silent drift, and the parity harness exists to catch drift, so do not introduce a
source of it.

Cascade order is guaranteed by one ordered import chain in `app/globals.css`:

```css
@import '../styles/tokens.css';
@import '../styles/base.css';
@import '../styles/chrome.css';
@import '../styles/sections/hero.css';
/* … one line per section, in the design's own source order … */
```

Global scope is safe because the design already uses strict `sdl-` / `ai-` / `bt-` / `de-` /
`dx-` / `gt-` / `evoq-` / `svc-` / `wae-` prefixes.

**Only three deviations from the design CSS are sanctioned** (plan §6.3): `next/font` replacing
the Google Fonts `<link>`, de-duplicating the ~45% shared chrome, and additive `:focus-visible`
rules. Anything else is a defect.

### Server Components by default

Nine client islands, and only these: `MegaMenu`, `MobileNav`, `HeroCanvas`, `InsightsCarousel`,
`ProductFilterTabs`, `TechGroupTabs`, `ContactForm`, `RevealObserver`, `ServicesDnaVisual`.
Everything else — every section wrapper, card, grid, heading and static SVG — ships zero JS.

### No slug-conditional logic in the route

Blocks that need collection data declare a resolver in `lib/cms/resolvers.ts`. The route resolves,
fetches and renders; it never special-cases a path. The reference project's catch-all route grew to
~380 lines of `if (fullSlug === 'contact')` branches that overwrote CMS content with hardcoded
strings — that is the specific failure this rule prevents.

### Registries, not database SVG

Blocks carry a string key; `lib/registries/` owns the artwork. Each registry exports both the
lookup and an `options` array, and the CMS imports the same option lists — so an admin dropdown
cannot drift from the code that renders it.

### Next 16 specifics

- `params`, `searchParams`, `draftMode()`, `cookies()`, `headers()` are **all async** — await them.
  `next typegen` generates `PageProps<'/route'>` for type-safe access.
- `revalidateTag(tag, 'max')` — the second argument is required; the one-argument form is a
  TypeScript error.
- `updateTag(tag)` for read-your-writes in Server Actions; `revalidateTag` in the webhook route.
- `proxy.ts`, exporting `proxy` — not `middleware.ts`.
- Framing is controlled by CSP `frame-ancestors`, not `X-Frame-Options`, so Payload's live preview
  can iframe this site from the CMS origin.

## Dependencies

Runtime dependencies are `next`, `react`, `react-dom`. That is the whole list, and it is
deliberate — the design is hand-authored CSS, inline SVG and a ported canvas animation. Adding a
UI, animation or component library needs a recorded decision in `docs/DECISIONS.md`.

**This app must never depend on the `payload` packages.** It talks to the CMS over HTTP only. The
single artifact crossing the boundary is `payload-types.ts`, generated in `cms/` and copied here
by CI.
